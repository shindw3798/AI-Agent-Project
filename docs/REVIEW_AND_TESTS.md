# 코드 리뷰와 회귀 검증

수정한 결함과 회귀 테스트 결과를 정리했다.

## 발견한 세 문제와 수정

| 문제 | v4에서 재현한 결과 | v5 수정과 확인 |
|---|---|---|
| 날짜를 서비스로 오인 | 날짜가 포함된 payments-service 질문에서 2026-10-20을 미등록 대상으로 처리 | 유효한 날짜만 제외. 등록 대상은 유지하고 실제 미등록 이름은 계속 확인. 날짜 관련 5개 테스트 통과 |
| 일반 대화가 다른 비동기 작업을 막음 | 0.25초 동기 API를 모의하면 0.01초 타이머도 약 0.251초 뒤 실행 | chat과 기존 write의 HTTP 호출을 to_thread로 분리. 이벤트 루프에서 작업을 해제할 수 있는지와 콜백 실행 스레드를 테스트 |
| 시작 실패 시 자원 정리 누락 | MCP 시작 후 모델 초기화 실패에서 MCP stop과 DB close가 호출되지 않음 | 시작 전 종료 콜백 등록, 부분 MCP 시작 실패와 취소 시 역순 정리. 단계별 실패와 정상 종료 검사 |

관련 파일은 `agent/targets.py`, `agent/openai_llm.py`, `server.py`, `agent/mcp_client.py`다. 새 회귀 테스트는 `tests/test_runtime_fixes.py`에 있다.

## 테스트 결과

기존 34개와 추가 14개, 총 48개 테스트가 통과했다. 실행 시간은 30.891초였다. 새 테스트의 구성은 날짜 5개, 비동기 호출 2개, 서버 초기화와 종료 5개, MCP 일부 시작 실패와 취소 2개다.

실제 MCP ops/docs 프로세스를 시작해 Tool 탐색과 모니터링 호출을 확인하고 연결을 모두 닫았다. 별도 포트 8107과 실패 주입 전용 8108의 실제 OpenAI 화면에서 5개 시나리오와 전체 절차, 정상 상태 보충 검증까지 완료했다. 기존 날짜 질문 검증도 보존했다. 이 검사는 모의 모니터링 데이터를 사용하며 고정 30문항 성능 비교와 별도다.


## 코드를 읽는 순서

1. `server.py`: API와 시작/종료 시 자원 관리
2. `agent/service.py`: 대화별 실행 제어, 같은 요청 재사용, 확인 질문 복원
3. `agent/graph.py`: 대상 확인, 조회, 검색, 작성, 검증 분기
4. `retrieval/index.py`: 문서 적용 조건과 의미 검색
5. `agent/action_catalog.py`, `validation.py`: 원문 조건 보존과 근거 대조


## 리뷰 후 남은 제한

- 유효한 YYYY-MM-DD 날짜만 제외한다. 다른 날짜 표기와 모든 자연어 별칭을 지원하는 범용 개체 인식은 아니다.
- to_thread로 이벤트 루프 차단을 줄였지만 취소된 요청의 동기 HTTP 작업 자체가 즉시 중단되지는 않는다. HTTP timeout 상한까지 끝날 수 있다.
- 규칙 검증은 원인과 최선의 조치의 의미적 정확성을 완전히 보장하지 않는다.
- MCP 호출은 공유 잠금으로 직렬화되는 부분이 있다. 대규모 동시 접속 성능은 검증하지 않았다.
- 새 PC 설치, 독립 사람의 내용 검토, 다른 모델의 최신 전체 비교는 남아 있다.
- 로컬 과제용 서비스로 인증, 권한, 운영 부하와 장애 복구 검증은 범위 밖이다.

세 수정 항목을 재현하는 테스트는 통과했지만 코드 전체에 결함이 없다는 보장은 아니다.

추가 UI 검사에서 대상 선택 후 이전 확인 결과가 이력에 남는 점을 확인했다. 첫 조치 조건 질문은 2단계만 선택했고, 전체 절차 보충 질문에서 1~5단계를 확인했다. 조건 보존과 단계 선택의 완전성은 구분한다. 이번 UI 확인 중 실행 코드 변경은 없었다.
